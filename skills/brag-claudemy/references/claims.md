# Claims policy: concept or built

The founder's rule for any product description: only reference capabilities that exist, and keep "works today" separate from "planned". A video makes that harder, because moving pictures read as working software.

## STATUS: BUILT

- Show the real product. Rebuild screens from the captured design, never paste screenshots of the app into a scene.
- Every on-screen line traces to the README, spec or a demo, with a [src: ...] tag in SCRIPT.md.
- No invented content, no testimonials, no numbers that are not in the source.

## STATUS: CONCEPT

- The product is a spec, not software. Every scene carries a visible "Concept preview" label (a single element above all scenes) and the end card says it again.
- All data on screen is invented and obviously so: a made-up case on example.test, made-up ids, a made-up client. No real person, case, domain or company.
- Never show prices, customers, users, accuracy, speed, or any multiplier or percentage. rulings.json forbids these as patterns in concept mode.
- Never name another product or vendor.
- Each on-screen claim still carries a [src: ...] tag, pointing at the spec requirement it comes from.
- Share copy says "concept preview" in plain words.

## Confidentiality

- No client names, no confidential material, no real case data, ever. Add the specific words to rulings.json "forbidden_words" at the start of the project.
- If a partner's data is under an NDA, nothing from it appears, even blurred.

## Copy

No emdashes, no double hyphens, none of: AI-powered, leverage AI, cutting-edge, game-changing, revolutionary. Practitioner voice, short sentences, no hype.
